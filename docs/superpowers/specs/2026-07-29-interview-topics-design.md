# 传家志 · 访谈体验改进设计（话题脚手架 + 录音保护）

## 一、背景与痛点

访谈页是产品核心闭环。现状:
- 开场:有照片走 Qwen-VL 看图开口;无照片走兜底引导。开场 prompt 已角色化("小传")。
- 提问质量:已接入 Validator 双 Agent(不重复/够具体),提问质量有保障。
- **缺口**:老人坐下后"不知道讲什么"。无照片时只给一个"直接开始"按钮,AI 泛泛开场,老人若没有现成话题容易发懵、冷场。
- 语音:点按录音 + 计时 + 脉动光圈,体验已达标;但录音过短(<2 秒)会走完整识别流程必然失败,白等一轮。

## 二、目标

1. **降低开口门槛**:无照片开场前,给一行家常话题 chip,老人点一下相当于"替他开口",AI 顺着这个话题问第一个问题。
2. **避免无效识别**:录音过短直接提示,不浪费一次云函数识别往返。

## 三、方案

### 1. 话题建议卡片(核心,纯前端)

- 显示时机:`!photoTempPath && messages.length === 0`(无照片、尚未开始)。选了照片或已开始对话即隐藏。
- 话题库(勾家族情感、口语好懂):童年往事 / 父母亲 / 老伙计 / 第一份工 / 过年 / 老房子 / 出远门 / 心里话。
- 点击行为:前端 `_pushMessage('user', 该话题的完整话术)` 再 `_askAI(history)`。相当于老人主动开口;chat 收到 `[user:话题]`(hasHistory=true)→ 走 chatWithValidation → AI 针对该话题提一个具体问题。
- **零云函数改动**:话题只是预填一条 user 消息,复用现有对话链路。

### 2. 录音过短保护(纯前端)

- `_onRecordStop` 进来先判 `recordTime < 2`:是则 toast"太短啦,多讲几句试试"并 return,不上传、不识别。
- 正常录音流程不变。

## 四、不做（范围控制）

- 不改 chat / asr 云函数(零部署)。
- 不做 AI 主动收尾引导(可能打断老人讲述,Validator 已保证提问质量,闭环按钮已存在)。
- 不动方言识别(粤语测试版现状,赛期范围)。
- 不做话题的个性化推荐(后续记忆层接入再做)。

## 五、涉及文件

| 类型 | 文件 | 改动 |
|------|------|------|
| 改 | `miniprogram/pages/interview/interview.js` | data 加 `topics`;`onPickTopic`;`_onRecordStop` 加短录音保护 |
| 改 | `miniprogram/pages/interview/interview.wxml` | 启动区下加话题 chip 行(`!photoTempPath && messages.length===0`) |
| 改 | `miniprogram/pages/interview/interview.wxss` | `.topics` / `.topic-chip` 胶囊样式 |
| 不碰 | chat / asr / genStory 云函数、Validator 逻辑、语音录音主流程 |

## 六、验收标准

1. 无照片进访谈页:看到话题 chip 行;点任一话题 → 出现老人气泡"我想讲讲…"→ AI 顺着话题问具体问题。
2. 选了照片或已开始对话:话题 chip 隐藏。
3. 录音不足 2 秒:提示"太短啦",不进入识别。
4. 正常录音、文字输入、生成故事等不受影响。
