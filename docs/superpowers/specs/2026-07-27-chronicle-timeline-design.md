# 传家志 · 家族时间线视图设计

日期：2026-07-27
关联主项目：`2026-07-21-chuanjiazhi-design.md`

## 背景与问题
家族编年志 `pages/chronicle` 目前是"书册"形态：封面 → 卷目(文字目录) → 按年代分章的故事卡片。
用户希望在最上方增加一条**可滑动的时间线**：一条横向的时间轴，轴上一个节点就是一篇故事，一眼看清整个家族史的时间脉络。
此外，老人口述的时间往往不精确（如"89 年的某一天"、"八十年代初"），时间线要能容纳这种模糊年份，正确归位排序，而不是因为解析不到年份就被踢到"岁月留痕"堆里。

## 方案决策（已与用户确认）
1. **位置**：改造现有编年志页，**不新增页面**。封面之下插入横向时间线，下方原有的分章卡片全部保留。
2. **方向**：**横向滑动**（左右拨动看不同年代），经典时间轴观感。
3. **数据来源**：复用编年志已有的 `fetchAll`（分页拉全部 story），不新增云函数、不改后端。

## 模糊年份的处理（核心需求）
现状 `parseYear` 只认四位数字（`/\d{4}/`），取不到就回退收录年——导致"89 年"、"八十年代初"这类被误判。
本设计在前端**增强 `parseYear`**，按优先级解析，统一归位到一个年份用于排序与定位，展示文案仍用原文兜底：
1. 四位年份（19xx / 20xx）→ 直接取。
2. 中文年代词（"八十年代" / "80 年代"）→ 取该年代首年（1980）。
3. 两位年份（"89 年" / "89"）→ 按家族故事多落在 20 世纪的常识补全：两位 ≥ 24 补 19xx，否则补 20xx。
4. 仍解析不到 → 回退故事收录年（`createdAt`）；收录年也缺 → 归入"年代不详"，排到时间线最末。

> 零后端改动：`era` 字段仍由 `genStory` 产出，前端解析增强即可兜住模糊时间，无需重新部署云函数、无需改 prompt。

## 交互
- 横向 `scroll-view`（`scroll-x`、`enhanced`、隐藏滚动条），内含一条贯穿的横线与等距排布的节点。
- 每个节点：上方年份标签（模糊的显示原文或"年代不详"）、中间圆点、下方故事标题（截断）。
- 点节点 → 跳转故事详情页 `pages/story?id=...`（复用编年志已有 `goToStory`）。
- 节点按年份升序排列（早年→近年），年代不详排末尾。
- 采用**等距排布**（每节点固定宽度，flex 横向排列），而非按年份差映射距离——后者计算复杂且跨度过大时节点会挤成一团，等距最稳、最直观。

## 视觉

- 节点圆点：`#A0522D` 实心 + 白边 + 轻阴影，与关系图节点同色系。
- 年份标签：`#A0522D`，字号 26rpx；标题 `#2B2218` 截断两行。
- 容器：白底圆角卡片，与编年志其它卡片统一。
- 配色沿用适老化体系（底 `#FBF7F0`、字 `#2B2218`、强调 `#A0522D`）。

## 文件改动
- 改 `miniprogram/pages/chronicle/chronicle.js`：增强 `parseYear`（认两位 / 年代词）；`loadChronicle` 在归一化后额外构造 `timeline` 节点数组（按年份升序，含 `_id / title / yearText / photoFileID / year`），挂到 `book` 数据里。
- 改 `miniprogram/pages/chronicle/chronicle.wxml`：封面下方插入横向时间线区块；节点复用 `goToStory` 跳转。
- 改 `miniprogram/pages/chronicle/chronicle.wxss`：时间线样式（横向滚动容器、横线、节点、圆点、标签）。
- `chronicle.json` 无需改动（纯原生 `scroll-view`，无第三方组件）。

## 风险与权衡
- 节点很多（几十篇）时横向很长，需左右拨动较多；属时间线的固有体验，可接受，后续可加"按年代聚合成一个节点、点开展开"的二级形态（本次不做，避免过度工程）。
- 两位年份补全（≥24 补 19xx）是基于家族故事时间分布的启发式，极端边界（如 23 年代）会误判；家族口述极少涉及 1823 这类年份，风险可接受，且回退到收录年兜底。
- `scroll-view enhanced` 模式在低版本基础库表现不一；用基础 `scroll-x` + `scroll-with-animation` 即可满足横向拨动，不必依赖 enhanced，降低兼容风险。
