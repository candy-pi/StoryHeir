# 传家志 · AI 记者化提升设计（故事引用原话 + 照片主动提问）

## 背景
功能链路已完整。冲奖的关键不再是堆功能，而是让 AI「更像一位有经验的口述史记者」、让成果「更像真实可信的家族史」。本轮做两个最高性价比改进，**每个都过案例测试、确认更优才采用**，不通过回退。

## 改进①：故事引用老人原话（genStory）
- **问题**：现 prompt 只在「纪实」风格提了句"保留原话"，warm/formal 没有，也没要求独立引用块。故事读着像"AI 写作文"，缺老人自己的声音。
- **改法**：SYSTEM_BASE 通用第 1 条加硬规则——正文中至少用「」独立引用 1～2 句老人访谈里真正说过、有画面感的原话，原样保留措辞，不得改写编造，自然融入不堆砌。三风格统一生效。documentary desc 去掉重复的"保留原话"（通用规则已涵盖）。
- **风险**：幻觉编造原话 / 堆砌引号 / 引用生硬 → prompt 三重约束（"真正说过""不得编造""自然融入不堆砌"）。
- **验收（硬门槛）**：测试脚本对同一段访谈跑新旧 prompt 并排对比，新版必须出现「」引用、引用内容来自访谈原文、整体更生动。不达标 → 调 prompt 或回退。

## 改进②：照片主动提问（chat · VL 持续观察，① 验证后启动）
- **问题**：Qwen-VL 只在首轮破冰用了一次（visionOpening），后续不再看照片——接了 VL 却浪费。
- **改法（低成本方案）**：首轮 VL 看图时，除开场提问外**额外抽取结构化"照片线索清单"**（合影人数 / 年长者 / 奖状 / 军装 / 自行车等值得追问的点）。后续轮次 GLM 拿线索清单 + 对话，在合适时机主动追问（"墙上那张奖状是谁得的？"）。**VL 仍只调首轮，不增调用成本。**
- **风险**：VL 线索 JSON 解析失败 → 降级只用开场提问；线索编造 → prompt 约束"只描述照片里确有的"。
- **验收（硬门槛）**：真机用一张有细节的老照片走完整访谈，VL 抽出 ≥2 条真实线索、且后续主动追问 ≥1 条。

## 执行策略：分步验证
先做①（改 prompt，可脚本自动对比，低风险）→ 用户跑测试确认更优 → 再做②（跨云函数 + 前端，真机验证）。每步"测试通过才采用"。
