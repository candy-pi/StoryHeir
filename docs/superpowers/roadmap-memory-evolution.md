# 传家志 · 从「AI 写故事」到「AI 持续构建家庭数字记忆」演进路线

> 本文件是总纲。十方向筛选、模块划分、依赖与实施顺序都在这里。
> 每个入选模块的详细设计见 `docs/superpowers/specs/2026-07-28-*-design.md`。

## 一、升级愿景

现状(已落地):一次采访 → 生成一篇 Story → 结束。生命周期短,AI 每次都从零开始。

目标:AI 成为**长期家庭记忆管家**——跨次采访累积同一个 Family Memory,主动发现人生空白、规划采访路线、验证提问质量。最终沉淀的不只是文章,而是一张**可查询、可传承的家族知识网络**。

```
现状:  采访 → Story → 结束
目标:  采访 → Story → 抽取实体入 Memory → 发现空白 → 规划下次 → 越来越完整
```

### 取舍理由
- **合并同源**:方向 1/2/3 本质都是"把 Story 抽成结构化实体并长期持有",合并为**模块 A(家庭记忆数据层)**——这是所有智能的地基,先打。
- **聚焦拿分**:用户推荐的三方向(知识图谱、空白发现、多 Agent)对应 A/B/C,优先投入。
- **轻量见效**:**模块 D(家风)** 独立、改动小、情感共鸣强,适合做热身或穿插。
- **暂缓 8**:多人实时冲突的产品流程复杂,单机 Demo 难呈现完整价值,留到赛后。
- **后置展示层**:E(多模态时间轴)、F(数字展馆)依赖前面的实体数据,放最后。

## 四、依赖关系

```
A 家庭记忆数据层 (地基,必须最先)
 ├─→ B 空白检测 + 采访规划 (依赖 A 的 events 算覆盖率)
 │     └─→ C 采访验证 Agent (与 B 的 interviewGoal 配合最强,也可独立)
 ├─→ E 多模态时间轴 (依赖 A 的实体)
 └─→ F 人生数字展馆 (依赖 A/B/D/E 全部)

D 家风提取 (独立,可任意时刻插入,建议作热身)
```

## 五、推荐实施顺序

**路线甲(拿分优先,推荐)**:`D`(热身见效)→ `A`(打地基)→ `B`(最大拿分)→ `C`(技术深度)→ `E` → `F`
- 先用 D 做一个轻量、能立刻在首页看到的成果,提振节奏;
- 再啃 A 地基(后续都依赖它);
- B 是比赛最亮眼的"AI 主动补人生空白";
- C 给 B 加质量保障,形成完整多 Agent 故事。

**路线乙(架构优先)**:`A` → `B` → `C` → `D` → `E` → `F`(纯按依赖,但不便早期演示)。

> 建议路线甲:Demo 友好,且 D 不依赖 A 可随时回退。

## 六、技术底座共性(所有模块复用)

- **memory 集合**:统一存抽取出的实体(`kind`: person/event/place/value),字段含 `familyId` + `sourceStoryIds[]` 反向溯源。详见模块 A 设计。
- **familyId**:当前为单家族 Demo,暂用固定 `"default"` 或用户 openid,字段预留,为未来多家族/分享留接口。
- **GLM 结构化抽取**:复用 `DASHSCOPE_API_KEY`,genStory 阶段一次性抽出实体(人物/事件/地点/价值观),降低额外调用成本。
- **chat context 注入**:每轮把 memory 摘要(人物清单 + 事件标题)注入 system prompt,让 AI"记得上次"。控制 token,只注入摘要不注入全文。
- **云函数运行时**:锁定 Node 16.13,新增代码需兼容(避免可选链滥用过新语法之外的特性基本无忧)。

## 七、暂缓方向(留档)

- **8 多人共同采访 + 冲突检测**:产品流程重,需要多人协同交互设计,Demo 难呈现。赛后或时间充裕再做。现有 contribution 的"补充/校对/认人"已是其轻量版。
- **方言模型细化**:依赖百炼 Paraformer 能力升级,非本项目可控,作为长线优化。
