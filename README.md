# 传家志（StoryHeir）

一个会主动采访老人的 AI 记者小程序——把家族老照片和口述记忆，整理成可以传下去的家族编年史。

参赛：2026 微信小程序开发大赛 · 主题「与 AI 共生」。

## 产品是什么

老人对着手机讲往事，AI 记者「小传」像晚辈一样追问——看老照片破冰、顺着线索深挖人物与情感；访谈结束后，一段段零散的口述被整理成带标题、年代、人物关系图的家族故事，最终汇编成一本按年代分章的《家族编年志》。

核心闭环：**选照片 → AI 看图提问 → 老人语音/文字作答 → AI 追问 → 生成故事 → 关系图/上色/朗读 → 编年志成书**。

全程为老人设计：大字号、高对比、大触控区、点按录音（不长按）、失败只给一句人话提示。

## 功能全景

### 小程序端（4 个页面）

| 页面 | 功能 |
|------|------|
| `pages/index` 首页 | 家族故事列表（云数据库实时刷新）、家风价值观墙（词云 + 详情弹层、频次定字号）、一键提炼家风、内置示例故事一键载入（评审 Demo 用） |
| `pages/interview` 访谈页 | 核心访谈闭环：选/补老照片、话题引子（童年往事/父母亲/过年…）、语音（普通话/粤语）或文字作答、故事风格三选（纪实/温暖/正式）、续访（从成稿故事继续追访）、一键成稿 |
| `pages/story` 故事页 | 故事正文 + 多图轮播、老照片 AI 上色、故事朗读（TTS）、人物关系图（原生 canvas 网状图，点边弹两人关系 + 同框情节）、家人共建（补充/校对/认人留言）、编辑标题正文、删除、分享到家族群 |
| `pages/chronicle` 编年志 | 全部故事按事件年代分章成书（模糊年份归一化：`89年`、`八十年代初`、正文历史时期词兜底）、时间线导航、家风封面、一键生成分享海报（离屏 canvas 绘制） |

### 云函数端（6 个）

| 云函数 | 职责 | 模型 / 服务 |
|--------|------|------------|
| `chat` | AI 记者访谈对话：首轮有照片走 VL 看图破冰并抽「照片线索」供后续追问；后续轮次走「生成 + 验证」双 Agent（Validator 卡不重复/够具体，不达标带建议重生成，≤2 次） | 百炼 GLM + Qwen-VL |
| `asr` | 语音转写：录音文件异步识别 + 轮询，保留语气词原貌 | 百炼 Paraformer |
| `genStory` | 访谈问答 → 家族故事：生成正文（含老人原话引用）、抽取人物/关系/年代，落库并关联访谈原文；支持续访更新 | 百炼 GLM |
| `restore` | 老照片 AI 上色，结果转存云存储并写回故事记录（家人共享） | 万相 wanx2.1-imageedit |
| `tts` | 故事朗读合成，音频缓存到 `story.ttsFileID`，二次播放 0 成本 | 百炼 Qwen-TTS |
| `extractValues` | 遍历故事提炼家风价值观，多篇印证（≥2 篇）才算数，清旧重写落库 | 百炼 GLM |

### 数据集合（云开发数据库）

| 集合 | 内容 |
|------|------|
| `story` | 家族故事：标题、正文、年代、人物、关系、风格、照片集、上色图、朗读缓存、关联访谈 id |
| `interview` | 访谈原始对话（可追溯） |
| `familyValue` | 家风价值观：词、印证篇数、代表原话、来源故事 |
| `contribution` | 家人共建留言：补充/校对/认人 |

## 前置准备

1. **注册小程序**：个人主体即可，拿到 AppID。
2. **开通云开发**：微信开发者工具 → 云开发，创建环境，拿到环境 ID。
3. **阿里云百炼 API Key**：[百炼控制台](https://bailian.console.aliyun.com/) 开通，一个 key 全部云函数共用（chat/asr/genStory/restore/tts/extractValues）。

## 配置

| 位置 | 改什么 |
|------|--------|
| `project.config.json` | `"appid"` 换成你的 AppID |
| `miniprogram/config.js` | `envId` 换成你的云开发环境 ID |
| 6 个云函数的环境变量 | `DASHSCOPE_API_KEY`（必填） |

云函数可选环境变量：

| 变量 | 作用 | 默认 |
|------|------|------|
| `DASHSCOPE_MODEL` | 文本对话模型 | `glm-5.2` |
| `DASHSCOPE_VL_MODEL` | 看图模型 | `qwen-vl-max` |
| `DASHSCOPE_VALIDATOR_MODEL` | 提问质量评审模型（可用更快更便宜的） | 同主模型 |
| `INTERVIEW_VALIDATE` | 设为 `off` 关闭双 Agent 验证（调试/降级） | 开启 |

## 部署与运行

1. 微信开发者工具导入本项目（填你的 AppID）。
2. **逐个部署云函数**：右键 `cloudfunctions/` 下 6 个目录 → 「上传并部署：云端安装依赖」。每个云函数目录里的 `config.json` 已配好超时（chat 30s、asr 40s、其余 60s），部署后可在云开发控制台核对。
3. **配环境变量**：云开发控制台 → 云函数 → 配置，给 6 个函数都加上 `DASHSCOPE_API_KEY`。
4. **建数据库集合**：云开发控制台 → 数据库，依次创建 `story`、`interview`、`familyValue`、`contribution` 四个集合，权限建议：
   - `story` / `familyValue`：所有人可读、仅创建者可读写（故事分享给家人可看）
   - `contribution`：所有人可读可写（家人留言）
   - `interview`：仅创建者可读写
5. **真机预览**：录音识别必须真机，模拟器录不到声音。

> 首页有「载入示例故事」入口：无 key、无录音也能撑起列表/关系图/编年志做演示，按标题去重可重复点击。

## 已知限制

- **数据隔离按 openid**：家风提炼只统计当前用户的故事；故事列表/家风墙读全集合，即同环境所有用户互可见——单家族共享场景如此设计，多家族需自行加隔离。
- **方言识别**：录音文件识别目前仅粤语（`paraformer-v2`），其它方言待接入 Fun-ASR。
- **分享可见性**：家人打开分享卡片需要 story 集合读权限放开（见部署第 4 步）。
- 云函数运行时为 Node 16，HTTP 调用统一用 `node-fetch` v2。
